`runner.py`、`scoring.py`、`state.py`、`backend.py`、`__init__.py` 和 `baseline/` 顶层归档文件均从已审核 v3 逐字复制。相对导入自然使用本目录的新 `cases.py` 和新 STAMP，后端路径自然仍指向项目的 `backend/`。不修改执行或评分实现。由此保留的组名 `improved_v3`、seed=20261020 和部分控制台说明属于执行兼容标识，不表示复用旧题或旧结果。

## 同组条件与预算

比较 `baseline_v2` 与 `improved_v3` 的完整方案。两组使用同一个模型、同一个真实 ProjectTools 序列化完整初始 context、同一批人类消息、同一输入 SHA、温度 **0.2**、每项总时限 **60 秒**、每项最多 **6** 个模型请求、SDK 重试 **0**。两组版本提示与内部工具方案不同，因此结果属于整体版本方案比较，不能声称是纯工具机制的因果效应。

6 评价例 × 2 组 × 2 重复 = **24 项**，每组 12 项；最坏 **144** 模型请求。全局上限 **180**，同时受已知可核验免费剩余额度的更小值限制，不因失败额外重试或切换付费模型。继承固定 seed=20261020，在每个重复中按题轮转、每题两组相邻，组先后交替。开发集 3 例单独导出，不计入评价分母。

执行前检查模型全部报价为零、免费请求剩余额度为已知正整数；任一报价或额度未知即停止。每次请求带全类型零价限制和禁回退配置；实际报告非零费用时停止。只允许 OpenRouter HTTPS 固定端点，两组都显式禁用 HTTP 重定向；307/308 等作为当次失败保存。预算在请求发出前消耗，失败请求也计数。

## 公共评分规则

评分逻辑与 v3 完全相同，两个组在相同层面打分。主指标基于 provider 最终公共 `output`，最后真实保存的模型响应另解析为 `raw_submission` 并独立诊断。不会从公共 output 补造原模型提交；原响应未返回或解析失败保持 null。JSON 字符串兼容修订可能使公共结果可用，但机械原候选解析仍保持原规则，不得悄悄用业务规范化改写原始提交。

先验证公共 AgentOutput schema、消息来源完整真实性及无重复、任务标识与依赖无重复、完成实体保护和真实 `check_plan`。合法 kind 与输入 mode 是否一致只作诊断，不是成功门禁；非法 kind 仍失败。错 ID、真正改动完成任务、重复 key 不能通过过滤洗白。

仅在上述原始检查后，将所有序列化业务字段与原任务完全一致的旧任务当作“未变冗余输出”精确过滤；依赖顺序不影响等价。其原始数量和冗余数量仍保留。有效变更按冻结别名、字段、日期允许集和验收词组匹配。无标签或重复匹配任务计入机械 hallucinated_tasks 指标，不等同于人工语义断言。

`semantic_success` 要求 schema、来源、标识、完成保护、约束、任务和字段全部正确。完整计划必须存在有效变更且没有未解决问题。缺信息场景必须空任务、问齐所有缺项；额外问题主题单独计数。`strict_success` 进一步要求无原样旧任务、额外/未知/重复问题，原模型候选也通过原始契约、来源、完成保护、约束，且没有缺信息仍补任务或无标签任务。原模型错误被生产关卡安全转为正确追问时，公共 semantic 可以成功，strict 仍会保留原候选错误影响。

问题主题正则与原评分器逐字相同，识别负责人、工时、开始、截止、验收、阶段、依赖、需求。未列明的表达可能被低估。人工复核意见可独立另存，不能改标签与机械分数。

未运行标 `not_run`。真实尝试中的网络、超时、格式和 None 输出失败均进入 attempted 分母。tokens、usage、费用缺失为 **null**，不能将未知当零；已知部分也不能补造未知部分。另列调用次数、耗时、约束、完成保护、原样旧任务和额外追问。

## 证据、恢复与可比性

默认 dry-run 不读环境凭据、不构造 SDK。只有显式真实执行路径读取进程中的模型和 Key，不读取 `.env`、`jwt.key` 或正式 data。每次尝试使用独立 SQLite 内存库和真实生产 ProjectTools、check_plan；不导入 app.main 或启动 Settings.prepare。

将来本轮锁只位于本目录，包含新 case/协议、逐字复用执行/评分源码、生产 agent/agent_output 及公共依赖、归档 baseline、共享 transport 的 SHA。冻结前保存完整计划和被测源码；源码快照与原始模型证据必须来自本轮，不拿旧 evaluated_source 替代。

manifest 保存模型、环境、预算、预检和 SHA；cases 保存同轮标签；records 保存完整24项；attempts 保存逐项状态和原请求/响应/工具证据；summary 聚合已保存评分。请求发出前及返回后、工具完成后原子保存。没有返回的 response 保持 null，异常或中断不删失败。

恢复以先提交的 attempt 为依据，但先验证计划、文件名、题号、组别、重复、完整序列化输入及 SHA，要求请求/工具前缀单调扩展，已知响应/用量/费用/结果不可丢失或改写。冲突先停止，不写文件。离线 summarize 保留已有终态评分；仍 running 的项按真实中断失败，不补造响应。不得通过离线 oracle 生成看似模型成功的正式记录。

只有 **live、完整、平衡、6评价例×2组×2重复** 的准确矩阵才允许版本排名；中断、不平衡、仅开发集或仅一次真实联调都不能评价两组优劣。首次真实结果无论好坏均原样保存，后续改进应另起版本和新计划。

## 候选验证的范围

`tests/test_protocol.py` 在本目录导入 runner/scorer/state/backend/cases，覆盖离线计划、SDK MockTransport、预算、零价、防重定向和证据恢复；它不把旧 module 的通过当本轮证明。`tests/test_candidate.py` 补充新身份/消息时间、外键、初态与修复可行性、所有9例 oracle、完成实体、输入标签隔离、归档逐字一致与旧结果/锁未改检查。原轮 SHA 清单另存 `protected_before.json`。

合成 oracle 直接从预先标签构造答案，只能证明标签内部一致、评分器能识别预设答案、真实公共约束可行；它不能证明模型会理解题目、调用工具或达到任何质量成功率。HTTP stub 也仅验证执行代码，不是真实模型证据。
