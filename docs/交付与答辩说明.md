# 本地交付与答辩说明

适用范围：Windows PowerShell 本地单进程演示。系统支持教师、组长、成员三种角色，覆盖初期、中期、最终三个阶段。交付包保留源码、依赖锁定文件、已有前端生产构建、文档和显式选择的证据。运行数据、账号签名文件及模型凭据由接收方另行准备。

## 1. 生成与核对交付包

打包脚本只使用 Python 标准库；不会启动应用、请求网络、读取 `.env`、`.env.stitch`、`jwt.key` 或正式 `data/`。从项目根目录执行：

```powershell
Set-Location D:\DevelopTools\biyesheji
& D:\Anaconda3\envs\face_env\python.exe -X utf8 .\scripts\package_delivery.py `
    --output work/delivery/course-collaboration-source.zip `
    --evidence work/backup-restore-result.json `
    --evidence work/acceptance/20261015T073627755077Z/result.json

& D:\Anaconda3\envs\face_env\python.exe -X utf8 .\scripts\package_delivery.py `
    --verify work/delivery/course-collaboration-source.zip
```

上例不包含固定样例真实实验结果。真实实验结束、完成离线汇总与结果复核后，明确指定该次运行目录，输出使用一个新的文件名：

```powershell
# 先把下面目录名替换为实际真实运行目录；不存在或 dry_run 目录会拒绝。
& D:\Anaconda3\envs\face_env\python.exe -X utf8 .\scripts\package_delivery.py `
    --output work/delivery/course-collaboration-20261015.zip `
    --results-dir experiments/results/eval-live-20261015-v2 `
    --evidence work/backup-restore-result.json `
    --evidence work/acceptance/20261015T073627755077Z/result.json
```

固定白名单为 `README.md`、根目录 `.env.example`、`backend/`、`frontend/`、`docs/`、`scripts/`、`experiments/`。`frontend/dist/` 包含打包时现有构建；若前端已变更，应先单独完成构建。所有 `node_modules`、缓存、`__pycache__`、`.git`、`data`、嵌套 `work`、环境文件及常见密钥/数据库文件被排除，根目录 `.env.example` 是环境文件唯一例外。

`experiments/results/` 默认整棵排除。`--results-dir` 可重复，只接受该目录下明确的一次运行目录，要求其 `manifest.json` 标记 `run_mode=live`；不会自动挑选最新目录，也不会把 dry-run 或测试 fixture 当作真实结果。该标记只用于区分运行方式，实验的真实性、覆盖数、停止原因及是否允许排名仍应结合原始记录复核。部分或失败的真实记录原样保留，不能因为被打包就写成完整对比实验。

`--evidence` 可重复，只接受 `work/` 内明确的单个报告文件或指定记录子树，归档中保留项目相对路径。不能选择整个 `work/`、备份目录、数据库、密钥或 `work/delivery/`。建议优先指定 `result.json` 等已脱敏报告；若需要整次记录，只选择该次运行的子目录。工具按路径和文件名排除敏感文件，不提供任意报告内容的自动脱敏，应先核对所选报告没有内嵌凭据。

输出只允许位于 `work/delivery/`，同名文件拒绝覆盖；输入输出路径均拒绝 `..`、越界、符号链接和 Windows junction/重解析点。脚本不会复制整棵 `work/`，也不会把备份恢复包混入交付。

ZIP 中的 `manifest.json` 逐项保存相对路径、字节数与 SHA-256。归档条目按路径排序，时间固定为 1980-01-01，权限固定，中文文件名使用 ZIP UTF-8 标记。同一 Python/压缩运行时、同一输入文件字节及参数会生成相同 ZIP 字节，不依赖源文件修改时间。`--verify` 检查文件集合及全部哈希，不解压、不执行文件；命令输出归档路径、文件数和整个 ZIP 的 SHA-256。哈希用于核对传输完整性。

## 2. 接收后的本地启动

将 ZIP 解压到一个全新的项目目录，不覆盖现有业务目录。保留随包的 `frontend/dist/`，先配置接收方自己的 Python 路径并安装后端依赖：

```powershell
Set-Location D:\DevelopTools\biyesheji  # 更换为本次新解压目录
$taskPython = 'D:\Anaconda3\envs\face_env\python.exe'  # 更换为本机 Python 3.12
& $taskPython -m pip install -r .\backend\requirements.txt

# 以下命令用于新解压、尚无 .env 的演示副本。演示库独立保存。
$env:DATA_DIR = Join-Path (Get-Location).Path 'work/defense-demo-data'
& .\scripts\Initialize-Demo.ps1 -Python $taskPython
& .\scripts\Start-Backend.ps1 -Python $taskPython -DisableAI
```

访问 <http://127.0.0.1:8000>。演示账号为 `teacher`、`leader`、`member1`，密码均为 `Demo2026!`；二组账号 `leader2` 可展示项目隔离。只在新演示副本初始化；已有正式服务直接启动并按既有 `DATA_DIR` 使用。签名密钥由新演示目录生成，不需要复制原机的 `jwt.key`。

交付包附带构建，因此上述启动无需现场安装前端依赖。需要修改或重新构建前端时，再运行 `Build-Frontend.ps1`；缺少依赖时会执行 `npm ci`，需要 Node.js 和网络。后端依赖也应在答辩前安装完毕。详细环境和脚本行为见[启动与演示说明](启动与演示说明.md)。

## 3. 真实模型与无模型两条路线

真实模型配置在服务端完成。仅当新副本不存在 `.env` 时，从 `.env.example` 复制；用本地编辑器填写 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`，同时明确 `DATA_DIR` 指向演示副本。不要把密钥写入前端、截图、命令历史、论文或 ZIP。地址与模型名称以自己供应商账户实际配置为准。

本项目曾在 2026-10-13 用 `https://openrouter.ai/api/v1` 和 `nvidia/nemotron-3-super-120b-a12b:free` 完成真实联调。该记录说明当时的兼容性，不保证答辩当天的可用性、免费额度或费用。配置后重启后端，不传 `-DisableAI`；若当前模型主机需要绕过本机代理，可按[模型联调记录](模型联调记录.md)使用 `-DirectModelConnection`。上线状态、响应与失败原因应以当次界面显示为准。

现场无网络、未配置模型或模型调用失败时，用 `-DisableAI` 启动。组长在计划页建立明确标记为“手工计划草案”的内容，填写任务、需求、负责人、工时、日期、依赖与验收条件；展示校验结果，修正冲突，成员反馈后由组长勾选确认发布。随后继续任务推进、计划版本比较与阶段审核。讲解时称为“人工草案流程”；不能把手工输入或测试替身称为 Agent 的真实输出。

## 4. 约 7 分钟答辩顺序

提前使用三个独立浏览器会话分别登录教师、组长、成员，准备第一阶段旧版本、中期材料与最终材料。所有演示材料标明“仅用于答辩演示”，演示通过不代表真实课程或学校已经验收。

| 时间 | 角色与操作 | 应说明的机制 |
| --- | --- | --- |
| 0:00–0:50 | 教师展示课程要求、初期/中期/最终三个阶段及团队公开进度 | 教师只能读取公开计划、进度与已提交成果，聊天室和内部分析不公开 |
| 0:50–1:40 | 组长展示成员技能、每周容量、需求与任务，再发一条讨论；成员会话看到消息 | 成员上下文与来源关联、实时同步及历史持久化 |
| 1:40–2:30 | 成员打开本人任务，填写进度、剩余工时与阻碍 | 本人权限；任务完成比例与阶段审核状态分开；不能发布计划 |
| 2:30–3:45 | 组长展示真实模型已有草案与来源；无模型时使用标记明确的人工草案。成员反馈后组长确认发布 | 来源可追溯、依赖/容量/日期校验、最终决定由人确认，版本保留 |
| 3:45–4:45 | 组长提交初期材料；教师查看旧“需要修改”意见与重提版本，再审核 | 每次材料、评语和关联计划形成快照，不覆盖历史 |
| 4:45–5:45 | 组长依次打开中期与最终提交，教师分别展示审核入口和历史 | 三阶段使用同一套提交/重提/审核规则；阶段状态独立 |
| 5:45–6:30 | 组长比较计划前后版本；展示二组隔离和教师内部数据拒绝的已有验收记录 | 完成记录保护、版本差异、跨项目隔离 |
| 6:30–7:00 | 展示测试/真实模型记录的范围、浏览器待验收项和备份恢复报告 | 区分自动测试、真实调用、页面实测与尚未完成事项 |

现场保留一条人工草案路线，并使用已有真实调用记录讲解模型步骤，避免将有限时间全部用于等待供应商响应。重提循环可集中演示初期阶段；中期和最终逐一展示各自的真实演示提交记录与审核状态，说明其范围。

## 6. 备份恢复与交付前复核

数据备份是独立操作，按[启动与演示说明第 5 节](启动与演示说明.md#5-备份与恢复)执行：先停止写入，运行 `scripts/backup.py`，恢复到全新目录并验证 SHA-256、SQLite、附件和历史记录，确认后保留原目录作为回退。备份含数据库、附件以及存在时的登录签名文件，应留在可信位置，不放入本交付 ZIP。

离线打包测试可独立执行，无需安装 pytest：

```powershell
& D:\Anaconda3\envs\face_env\python.exe -X utf8 -m unittest discover `
    -s scripts/tests -p test_package_delivery.py -v
```

打包前完成需要的代码测试与前端构建，确认论文中的实验范围与最终结果一致；生成 ZIP 后运行 `--verify`。把命令输出的 ZIP SHA-256 与交付文件一起交给接收方，并在新目录解压后按本说明走一遍无模型演示，再决定是否现场调用真实模型。
