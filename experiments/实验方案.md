# 实验方案与冻结边界

## 研究对象

研究问题是：在相同模型下，增加项目业务上下文及项目工具/约束反馈，是否改善讨论抽取与可行规划。只有实际结果能够支持结论。失败、无改进和不可行样例完整保留。

| 方法 | 可见信息 | 工具 | 单次分析请求上限 |
| --- | --- | --- | --- |
| `chat_only` | 固定聊天室消息、消息时间、共用名称编号目录 | 无 | 1 |
| `context_only` | 与 Agent 完全相同的完整 `ProjectTools` 上下文和消息 | 无 | 1 |
| `agent` | 相同完整上下文和消息 | 生产 `get_project_context`、`get_tasks`、`check_plan` | 6 |

三组使用生产 `PROMPT`、同一 `AgentOutput` 协议、同一所选模型和温度 `0.2`。两组基线不传 `tools`，不强制 `response_format`；Agent 直接复用生产 `OpenAIProvider.analyze`，实际 `create` 被包装以记录、计数并增加统一零价路由保护。Agent 在需要时可重新查询并用约束反馈修正。生产提示中“调用 check_plan”的指令对无工具基线没有执行能力，这是整体方案的一部分，应在论文中明确。

名称编号目录三组共用，只包含成员姓名与编号、需求标题与编号、既有任务标题与编号/键、旧卡标题与编号。目录不含容量、日期、课程期限、需求状态、负责人或旧卡的任务细节。这样避免编号不可获得的形式性失败，也明确了 `chat_only` 无法掌握旧卡参数、负载或已有依赖的限制。

`chat_only` 与 `agent` 比较包含信息范围差异。`context_only` 与 `agent` 的初始业务信息相同，但工具反馈与多次调用预算仍不同。任何一组比较都不能直接解释为“纯工具调用的因果提升”。若需要该结论，必须另行设计等预算、消融与随机化实验，不能事后改写本次解释。

## 样例和固定状态

开发集 3 个、评价集 10 个，详见标签说明。两集 ID 与业务消息分别管理。评价集标签在看模型输出前冻结。`cases.py` 的业务时间固定为 `2026-10-16T09:00:00+08:00`；所有项目、需求、任务、卡片、消息数据库时间显式填写。相对日期只根据来源消息解释，不使用运行日期生成提示。

每个方法、样例、重复次数单独新建 SQLite 内存数据库，装载相同初始状态，使用真实 `ProjectTools`、`AgentOutput` 和 `check_plan`。无正式数据读写，无 Web 服务启动，无真实发布。

默认评价集重复 2 次，共 60 个分析尝试，最坏调用数为 `10 × 2 × (1+1+6) = 160`，全局默认上限 180。固定 seed 与轮转交错顺序写入 manifest。预算不足时保持完整 planned 清单，已产生记录继续保留，剩余项为 `not_run`。不删样例、不延长预算、不偷偷换模型。

## 冻结和执行

`freeze.json` 包含全体样例（开发及评价）的 SHA-256 和协议 SHA-256。协议涵盖评价代码、生产提示、输出 schema、provider、真实校验器、数据模型和序列化等源码。真实运行前重新计算并严格核对。独立审查完成之前，不执行 `--live`。发现评价输出后不得为提高分数修改冻结标签、生产提示或该轮评价协议；协议修复必须另列版本，保留旧结果与修复原因，重新预注册后才能建立新轮次。

真实运行只从进程环境取得凭据；预检只保存价格、额度等白名单字段，丢弃可能含密钥片段的 key label。错误、请求和响应中的秘密和登录令牌脱敏。OpenRouter 的零价、额度和实际费用检查依据当前元数据，不把事前报价视为实际费用。接口 401/402/403/429、已知非零费用、预算用尽会停止余下调用。其余失败独立保留，不自动重试。

## 报告与解释

报告任务抽取和字段抽取的 TP/FP/FN、精确率、召回率和 F1；报告必要问题覆盖、更正卡关联、意外/重复追问、重复或未匹配任务；报告真实校验器逐类约束通过数、约束通过比例及全部约束通过的非空计划比例。澄清与不可行判断分开报告。

计划可行率的分母仅包含期望产生非空可行计划的实际尝试。它们的非法输出、异常和空任务均视为不可行；不允许空任务利用 `check_plan` 对既有状态的通过刷分。澄清/不可行的空任务不计入可行计划分母。所有 `not_run` 都不进入已尝试成功率、F1 或可行率分母。

`comparison_complete`、各组覆盖数及 `comparison_balanced` 置于汇总顶层。未完整或不平衡时，不据部分样本进行全套比较或排名。报告样例级、重复级结果及失败分布，不把同一样例多次运行当成独立新项目。样例小且人工设计，不能推广成真实学生团队的平均效果或稳定生产准确率。

`elapsed_ms` 为本次分析端到端耗时（包含隔离状态/上下文准备、模型、工具、schema 和评分）；API 请求耗时另外逐次保存。本框架不测 WebSocket 消息传播延迟或生产队列延迟，相关指标须从系统测试记录另行报告。用量与 `usage.cost` 原样保存，无法取得的项为 `null`；不会根据 token 报价估算实际账单。
