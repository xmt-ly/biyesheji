# Design System: 课协 · 课程项目智能协作系统

用途：Google Stitch 页面生成与迭代的统一设计规范。由已安装的 StitchDesign 插件中的 stitch-design-taste 流程整理，依据现有需求和业务实现编写。本文件是设计输入；尚未代表 Stitch 在线生成的页面结果。

## 1. Visual Theme & Atmosphere

课协面向本科课程项目团队。界面像一间整理有序的课程工作室：平静、清晰、有适度的信息密度，强调讨论如何转为成员行动。学生进入后应迅速找到本人任务、团队讨论、待核对安排和阶段反馈。

密度 6/10，布局变化 5/10，动效 3/10。桌面优先，兼顾手机。采用浅色中性底、单一松石绿强调色、无衬线中文排版；内容优先，装饰克制。非对称布局用于区分主要工作与辅助信息，表格和工作看板保持稳定的阅读秩序。

教师端服务于发布课程任务、观察公开进度和检查阶段成果。教师不进入学生聊天室，不看到内部 Agent 卡片、来源消息或运行记录。

应用内页不使用营销式大标题和大面积宣传 Hero。登录页允许一处具有记忆点的视觉：左对齐标题中嵌入一个字高的协作流程小图，表达“讨论 → 核对 → 行动”，其余区域保持安静。

## 2. Color Palette & Roles

全站使用同一组 Zinc 中性灰，不混合冷暖灰。只有一种品牌强调色，饱和度低于 80%。

| 描述名称 | 色值 | 用途 |
| --- | --- | --- |
| 纸面白 Paper Canvas | `#FAFAFA` | 页面底色，提供安静的阅读背景 |
| 内容白 Surface White | `#FFFFFF` | 工作区、输入框与弹窗内部 |
| 浅锌灰 Zinc Wash | `#F4F4F5` | 分组背景、表头、悬停底色 |
| 结构灰 Structural Line | `#E4E4E7` | 分隔线、输入边框与网格结构 |
| 深锌墨 Zinc Ink | `#18181B` | 主文字、关键数值；代替纯黑 |
| 次级墨 Secondary Ink | `#52525B` | 说明、作者、时间等辅助信息 |
| 松石绿 Studio Teal | `#2F6F65` | 唯一品牌强调色，用于主要动作、当前选中项和焦点边框 |
| 淡松石 Teal Wash | `#EEF5F3` | 同一强调色的低强度底色，用于选中区域和核对记录 |

不同状态同时使用文字、线性图标与边框，不依赖红黄绿颜色区分。错误以深墨色警示图标、明确原因和修正动作呈现；“需要修改”与“待审核”必须写清。焦点边框使用 Studio Teal，不能使用霓虹光晕。

正文与背景对比至少 4.5:1，大字至少 3:1。次级墨用于需要读取的辅助信息，较浅灰只能用于边线和禁用装饰。禁止纯黑、紫色 AI 光晕、蓝紫霓虹渐变、渐变文字和高饱和按钮。

## 3. Typography Rules

- 中文使用 `Noto Sans SC`；英文字母和短标题使用 `Geist`。统一字体顺序为 `Geist, Noto Sans SC, PingFang SC, Microsoft YaHei, sans-serif`，所有中文页面必须检查真实中文字体效果。
- 时间、日期、工时与版本号使用 `Geist Mono` 或 `JetBrains Mono`，中文说明仍为正文无衬线字体。表格数字采用等宽数字。
- 页标题 28px，字重 650，行高 1.3；小屏使用 `clamp(1.5rem, 2vw, 1.75rem)`。区块标题 18px，字重 600；卡片标题 16px，字重 600。
- 正文 15px，行高 1.65；表单文字与按钮 14px，辅助信息最低 14px。长说明最大 65ch，中文讨论每行尽量控制在 30～38 字。
- 层级由字重、间距和颜色形成，不以极大字号制造视觉冲击。中文不使用额外负字距，短英文标题可使用 -0.02em。
- 禁用 Inter；软件界面禁用衬线字体。禁止大段全大写标签、每个标题上方重复装饰性英文小字。

## 4. Component Stylings

### 按钮与导航

主要按钮为松石绿实底、白色文字，圆角 8px，桌面高度 44px。一个局部任务区只出现一个最主要动作。次要动作用白底边框或文字按钮。按下时轻微下沉 1px，禁止外发光和自定义鼠标光标。

侧栏宽 224px，白色底，右侧 1px 结构线。顶部为“课协”和简短产品说明，项目切换紧随其后。导航使用统一的线性 SVG 图标，选中项采用淡松石底、深绿文字和清晰左边界。账号和退出入口位于底部。

### 信息容器与表格

卡片只用于可独立执行的工作对象或需要隔离的层级，如任务、Agent 建议、阶段提交。圆角 12px，边框 1px；弹窗圆角 16px。顶层浮层可使用 `0 8px 28px rgba(24,24,27,0.06)`，普通容器不叠加阴影。

需求、团队成员、版本差异优先使用表格、分隔线和留白。禁止将所有信息切成同尺寸卡片。不要使用三个等宽营销功能卡组成一排。

任务卡呈现任务名、关联需求、负责人、截止日期、剩余工时和状态；阻碍以文字标记及图标展示。任务详情中的说明、验收条件、依赖和日期始终可见，成员编辑进度时不能隐藏这些依据。

### 聊天与 Agent 建议

人类消息采用紧凑的讨论流：头像、姓名、时间、正文，自己的消息也保持可读的内容宽度。头像使用中文角色简称或 SVG，不用图库照片和 emoji。

Agent 建议是独立分析容器，必须呈现来源、明确问题、约束结果及建议状态。不能做成悬浮聊天机器人吉祥物。来源消息可定位，纠正和成员反馈可展开。未发布建议必须清楚写明“草案”。

“人工草案”“智能分析”使用文字标明来源。未启用助手、分析中、失败、等待补充、失效和已发布是不同状态；失败有明确重试入口，人工协作仍可进行。

### 表单、弹窗与错误

标签位于输入框上方；输入高度至少 44px，文本域至少 100px。必要字段说明放在附近，错误置于字段下方。任务工时、负责人和日期用用户可理解的标签，不展示数据库 ID、JSON、API 术语或提示版本。

任务详情使用右侧抽屉；整份计划核对使用宽弹窗；最终发布单独确认，写清会生成计划版本并更新任务。危险或不可逆动作不放在首要按钮位置。

提交失败保留用户输入。团队刷新不能覆盖未保存的资料草稿。按钮等待状态保留原尺寸及动作名称，使用低强度扫光或条形等待指示，不用 generic 环形 spinner。

空状态必须说明下一步，例如“还没有团队讨论，先说说你准备完成的任务”。骨架加载与最终内容尺寸一致；禁止无依据的占位统计或伪造模型结果。

## 5. Layout Principles

桌面参考画布 1440 × 1000，工作内容最大宽度 1400px。页面水平内边距 32px、区块间距 24px，密集行内部间距 12～16px。使用 4/8/12/16/24/32/48px 间距尺度。

主骨架为侧栏、64px 顶栏和内容区。顶栏展示当前项目、页面名称、搜索或刷新动作和账号入口。内容区优先放关键工作，再放统计；不让 KPI 卡片占据首屏主要空间。

- 学生工作台：主列约 2/3，展示“我的下一步”和本人任务；辅列约 1/3，展示待核对安排和阶段提醒。项目切换是入口，教师任务不是学生首页主角。
- 团队协作：聊天区约 62%，建议区约 38%。消息列表与输入区属于一个工作容器，输入区稳定在其下方；建议区有自己的滚动区域，明确选中来源。避免嵌套三层滚动。
- 任务看板：待开始、进行中、已完成三个业务阶段采用约 32% / 44% / 24% 的区域比例，突出正在推进的工作。状态切换以按钮/详情表单可操作，不假设必须支持拖拽。
- 计划与排期：上方为版本选择和变更说明，中间是对比表及时间安排，下方是依赖和按周工时解释。比较必须同时看得见前后值。
- 教师审核：左侧阶段与提交版本列表，右侧较宽的交付物、提交说明、进度快照和审核表单。三个阶段用顺序列表或时间线，不用三个等宽宣传卡。

采用 CSS Grid 思路描述布局，不使用百分比 calc 拼凑宽度。元素不得互相覆盖，正文不与照片重叠。固定布局高度使用动态视口的最小高度思路，避免手机地址栏造成跳动。

### 响应式

1024px 以下侧栏可收起；768px 以下所有多列内容折叠为一列。手机聊天页用“讨论 / 建议”切换；任务页用状态筛选展示单列任务；教师审核先选阶段和提交，再显示详情。没有横向页面溢出。

表格在小屏转为逐条记录比较，时间安排转换为日期区间列表。所有点击目标至少 44 × 44px。手机表单使用全宽抽屉或底部面板，关闭和提交始终容易找到。

## 6. Motion & Interaction

动效用于解释打开、选中、发送、核对和发布的结果。默认过渡 140～180ms；抽屉/宽弹窗约 220ms。需要弹性时采用接近 stiffness 100、damping 20 的重量感，不能夸张回弹。

新消息轻微淡入，新的建议容器按 24ms 间隔进入，总时长不超过 220ms；历史消息补取时不重新播放整个列表动画。活跃状态的循环微动效限于正在分析、上传或同步的组件，采用 2.8s 低强度 opacity 呼吸或 skeleton 扫光，任务正文保持静止。

只对 transform 和 opacity 做动画；不动画 top/left/width/height。页面在后台时停止循环，尊重 `prefers-reduced-motion`，减少动态模式下禁用循环和位移动效。不得自动打字显示重要结果、循环漂浮任务卡、闪烁警告或反复动画每条历史消息。

## 7. Anti-Patterns (Banned)

- 没有 emoji、Inter、衬线软件标题、纯黑、霓虹外发光、饱和渐变和巨型渐变文字。
- 没有每页通用 Hero、无意义的装饰 KPI、三个等宽营销卡、无关库存照片和机器人插画。
- 没有“赋能、无缝、革新、下一代”等宣传填充词；动作使用“保存进度、核对草案、发布计划、提交阶段成果、保存审核意见”。
- 没有数据库 ID、API 字段、模型密钥或部署方式进入普通学生业务流程。
- 没有假的准确率、成本、贡献分、固定漂亮百分比或假装由模型生成的分析。设计样例必须标为演示数据。
- 没有教师聊天室入口或私有 Agent 侧栏；不能把教师审核通过自动等同于成员任务完成。
- 没有完成任务自动重排、没有未核对草案直接生效、没有用红黄绿颜色单独表达状态。
- 没有无意义“向下滚动探索”、弹跳箭头、自定义鼠标、元素叠盖或手机横向溢出。
