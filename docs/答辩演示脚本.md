# 答辩演示：课程资料共享平台

这份数据用于讲清系统业务闭环。所有预置讨论、任务、草案、材料和评语均为**人工编排的【答辩演示】**，两张卡片均标明**【人工备用草案】**。初始化不调用模型，不读取根目录 `.env`，不连接正式数据库。Agent 的真实能力、失败与限制应依据另外保存的真实模型评估报告说明，不能把这里的人工卡片当成模型输出。

## 初始化与启动

在项目根目录执行以下命令。初始化每次创建 `work/defense-demo/<UTC时间戳>/`，其中独立保存 SQLite、附件和随机生成的签名密钥；不会覆盖已有目录，也没有重置或 `--force` 选项。先完成工具测试与评审，再执行初始化。

```powershell
$env:PYTHONDONTWRITEBYTECODE = '1'
& 'D:\Anaconda3\envs\face_env\python.exe' -X utf8 scripts/seed_defense_demo.py
```

需要固定排期基准时使用 `--reference-date 2026-10-18`；默认使用运行当天。需要自定义目录时使用 `--data-dir` 指向项目 `work/defense-demo` 下的**全新**子目录。正式 `data`、范围外路径、已存在目录、符号链接和 Windows junction 均拒绝。

初始化输出完整数据目录。检查该目录 `manifest.json` 的 `status` 为 `passed`，再启动同一目录：

```powershell
.\scripts\Start-DefenseDemo.ps1 -DataDir 'D:\DevelopTools\biyesheji\work\defense-demo\<初始化输出目录>'
```

默认访问 `http://127.0.0.1:8001`，正式实例常用的 8000 端口保持独立。页面由现有 `frontend/dist` 提供；应先确认项目已有前端构建。启动脚本不构建前端、不重新初始化数据，退出服务按 `Ctrl+C`。不要把演示服务改到正在占用的正式端口。

服务启动和模型配置加载前，会先用隔离 Python 运行纯标准库只读校验：演示目录全部后代（含 `files` 和附件）不得有 symlink、junction、其他 reparse point 或文件硬链接；数据库以 `mode=ro&immutable=1` 打开，通过完整性和外键检查，具备当前模型要求的全部业务表/列、演示账号、课程与两团队、计划/提交记录及原始材料。仅有 SQLite 文件头、空库、缺表/缺列或未初始化数据不能启动。校验不导入应用、不读取 `jwt.key` 内容、不自动建表或修库，也不产生 SQLite 辅助文件。

应先干净关闭该演示库的写入实例。若存在 `collaboration.db-journal`、`-wal` 或 `-shm`，启动器会拒绝，需先正常关闭写入并排查；它不会尝试恢复、删除或覆盖文件。也可单独验证已有目录：

```powershell
& 'D:\Anaconda3\envs\face_env\python.exe' -I -B -X utf8 scripts/seed_defense_demo.py --validate-existing --data-dir '<完整演示目录>'
```

默认不读取 `.env`，并清空继承的模型配置，AI 关闭。只有明确需要现场调用真实模型时才加 `-EnableAI`，脚本此时只加载根 `.env` 中的 `LLM_*`；配置加载后仍强制设置独立 `DATA_DIR`、清除继承的 `JWT_SECRET`，由演示目录自己的 `jwt.key` 签名。**开启 AI 可能恢复初始化留下的待处理讨论意图并产生真实模型调用和费用。**

```powershell
# 仅在明确选择真实模型演示时执行；此步骤不属于离线初始化验收。
.\scripts\Start-DefenseDemo.ps1 -DataDir '<完整演示目录>' -EnableAI -DirectModelConnection
```

`-DirectModelConnection` 只把模型主机追加到当前进程 `NO_PROXY`，保留既有主机，不修改系统代理；必须同时指定 `-EnableAI`。可用 `-Python` 选择解释器、`-Port` 选择其他空闲端口。

## 账号与数据

六个公开演示账号密码均为 `Demo2026!`，仅用于本地演示。

| 角色 | 账号 | 演示职责 |
|---|---|---|
| 教师 | `teacher` | 发布课程、查看公开计划与进度、审核阶段材料 |
| 一组组长 | `leader` | 确认需求、人工草案、发布计划、提交阶段材料 |
| 一组成员甲 | `member1` | 资料上传与分类，6小时，每周12小时容量 |
| 一组成员乙 | `member2` | 授权检索与下载，8小时，每周12小时容量 |
| 二组组长 | `leader2` | 独立团队的权限对照 |
| 二组成员甲 | `member3` | 独立团队成员 |

`manifest.json` 包含绝对数据目录、参考日、角色账号、课程与项目ID、两版计划、五次提交、五份材料的 SHA256 以及逐项验收结果，不记录登录 token 或签名密钥。主项目是【答辩演示】一组课程资料共享平台；二组是权限隔离对照，不预置额外任务或审核。

演示是按实际业务顺序压缩重放，所有 `created_at` 都是真实初始化时间；任务排期和课程截止日按参考日推导，未回填过去时间。不能把几秒内的初始化记录解释为真实连续数周的项目运行。

## 建议讲解顺序（约 6 分钟）

1. **教师，课程要求（约30秒）。** 登录 `teacher`，打开“课程任务”，选择【答辩演示】课程资料共享平台。展示两项必做功能、明确验收条件和三个检查阶段。说明教师定义课程目标，团队决定内部执行细节。
2. **组长，讨论到首版计划（约70秒）。** 退出后登录 `leader`，进入一组项目和协作页。从讨论记录中展示两名成员对负责人、6/8小时、绝对日期和依赖的明确承诺。打开【人工备用草案】首版分工与排期，展开“成员反馈与修改记录”，展示两名成员确认。指出该卡片是人工备用，组长发布才产生公开计划v1。
3. **成员推进与调整（约70秒）。** 查看成员甲“本人推进25%，剩余4.5小时，等待分类样例”的任务评论及后续消息。打开【人工备用草案】延期与依赖联动调整，展示首任务截止顺延两天、后续任务开始和截止同时顺延。对比计划历史v1/v2：v1首任务进度0；v2冻结为25%，成员乙任务开始晚于前置截止。
4. **公开计划与阶段历史（约90秒）。** 回到阶段成果，展开初期v1“需修改”与v2“通过”，两次均保留计划v1和0%任务完成快照。中期v1“通过”保留计划v2与50%；最终v1“需修改”、v2“通过”均为100%。强调“任务完成比例100%”与“教师验收通过”是两个不同判断。旧评语、旧材料和旧进度快照不会被后续变化覆盖。
5. **教师与隐私边界（约60秒）。** 登录 `teacher`，选一组项目，查看公开任务进度、两版计划、三阶段五次提交和评语，下载初期v1与最终v2材料。说明教师下载范围由“已提交材料”授权，不能进入团队内部聊天室、草案、附件列表或 Agent 记录。二组账号也不能读取一组内部数据。
6. **真实 Agent 能力（约40秒）。** 展示单独的真实模型评估报告和真实输出，说明 Agent 提建议、追问与检查，组长最终发布。这里两张人工备用草案仅保证业务闭环可重复讲解；模型未配置时仍可完成协作和审核。

初始化结束时两个任务都已完成，页面主要用于查看完整历史。成员25%和阻碍保存在评论、讨论、计划v2及提交快照中；需要在现场展示“修改本人任务”的按钮流程时，应另外创建新项目/未完成任务。已完成任务受业务保护，不应回退现有完成状态来伪造现场过程。教师权限拒绝和成员更新由隔离 API 测试验证，页面是否提供对应入口应以当前版本现场检查为准。

| 阶段/版本 | 计划快照 | 任务完成比例 | 真实业务审核结果 | 材料重点 |

每份 Markdown 文件都写有“仅用于答辩演示”，经真实文件上传、组长提交、教师审核 API 创建。审核状态没有直接写数据库；只有无注册 API 的六个演示账号通过应用自己的密码哈希逻辑初始化。教师下载字节与上传字节逐一比较，并在 manifest 保存哈希。

## 工具验证与限制

以下测试只在 `--basetemp` 指定的 C 盘临时目录创建隔离数据，运行真实 ASGI/API，不请求外部 HTTP，也不创建项目正式演示库：

```powershell
$env:PYTHONDONTWRITEBYTECODE = '1'
& 'D:\Anaconda3\envs\face_env\python.exe' -X utf8 -m pytest scripts/tests/test_defense_demo.py -q -p no:cacheprovider --rootdir . --basetemp 'C:\Users\XMT18\Documents\Codex\defense-demo-tests-<新目录>'
```

测试覆盖重启后两版计划、五次审核与材料、教师私域403、二组隔离、本人25%更新及完成保护、重复初始化不改库、正式路径/越界/链接拒绝、模型配置隔离及零 Agent 运行，以及 PowerShell shim 验证默认8001/关闭AI和 `.env` 无法覆盖演示 DATA_DIR。启动专项验证附件根目录/嵌套 junction、附件硬链接、伪 SQLite 文件头及无业务表的 SQLite 均在服务启动前拒绝，并核对原库字节及目录项不变；独立只读验证还禁止读取密钥或调用业务应用加载器。Windows asyncio 自唤醒使用内部回环 socketpair；API测试禁止实际 HTTPTransport 和外部 socket 连接。

这组工具验收不替代浏览器交互验收、真实模型评估或数据库备份。初始化失败时保留失败目录供排查，不自动删除；换一个全新目录重试。业务数据库、附件、manifest 和演示密钥应作为一个目录保留，避免只复制数据库导致材料缺失。
