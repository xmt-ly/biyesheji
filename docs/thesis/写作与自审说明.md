## 2. 已核对的实现事实

按实际 15 个 ORM 类统计物理表，没有把 JSON 任务依赖虚构成独立数据表。教师无聊天室、内部卡片、内部 Agent 运行访问及 Agent 私聊。模型工具只有当前项目查询和检查，正式发布受组长权限、修订号、来源、完整集合检查和数据库事务约束。

当前模型循环最多 6 轮、每轮最多 5 个工具调用，默认 60 秒模型交互超时，不等于包含消息聚合的端到端上限。消息聚合默认静默 3 秒、最长 15 秒。AgentIntent 与业务操作共同提交，独立于消息游标，失败不因重启无限自动重试。新任务硬性禁止冒用 `task_` 前缀，`new_` 是提示约定，未写成 schema 强制前缀。

成员反馈被保留，但服务端没有强制全员签署；发布前端要求组长勾选确认。阶段流程有三个阶段，接口没有强制顺序解锁，也不会在最终通过时自动归档。任务数量占比、结构覆盖与日粒度容量近似均没有写成教学成效或最优排程。

前端状态保护已对照 `workspace.js`、`state.js`、`memberDraft.js`、`TaskDetails.vue` 与 `CardsPanel.vue`；任务表单按打开时快照产生差异，权限与展示使用当前状态。计划比较使用历史快照，未把当前任务回填旧版本。
