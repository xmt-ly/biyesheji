# Agent 可靠性诊断

日期：2026-10-17。依据 10 月 15 日保存的真实记录进行只读复核，没有重新调用模型或改变旧标签。

## 失败归因

Agent 组 20 项中，7 项严格成功，7 项有结构输出但未满足全部冻结标签，6 项超过 60 秒总分析预算。13 项未成功可按主要原因拆为：

| 主要原因 | 数量 | 证据 |
| --- | --- | --- |
| 总分析预算超时 | 6 | E02 R1、E04 R2、E05 两次、E07 R2、E10 R2；其中 5 项已经形成通过检查的候选 |
| 阶段标签假设 | 3 | E01 两次、E06 R2；模型选择最终阶段，冻结标签为开发阶段，来源未明确阶段，业务约束均通过 |
| 完全未变化的既有任务 | 3 | E07 R1、E09 两次；总计 7 个不必要的旧任务进入输出，增加机械 FP，但完成任务原值未改变 |
| 缺失事实被补造 | 1 | E02 R2 输出李华、3 小时、10 月 21—22 日，来源没有这些事实；E02 R1 超时前的检查参数也出现同类行为 |

原始位置为 `experiments/results/eval-live-20261015-v2/`。7/20 是特定协议的严格整案比例，不是系统整体可用率。

## 调用与协议问题

44 次模型请求对应 24 次工具调用：18 次 `check_plan` 全部通过，另有 6 次重读初始上下文。E07 R2 对完全相同候选重复检查，在额外往返后超时。API 请求耗时累计 946.030 秒，端到端 953.954 秒；没有独立工具计时，不能把差额直接归因为工具开销，也不能仅凭超时判断网络故障。

现有 provider 对无工具调用的消息直接执行 `json.loads`，结构校验在 Manager 中进行，因此坏 JSON 和缺字段没有有限修正机会。工具成功后仍需要一次最终自然语言 JSON 回复，已验证候选可能在这一轮等待中丢失。初始上下文已经完整预查，查询工具仍始终开放。新任务的事实充分性只靠提示，业务约束检查不能证明负责人或工时在讨论中得到支持。

## 本轮修复边界

增加结构化 `finalize_analysis` 提交工具，由程序执行最终 schema、来源、未变任务规范化与规划检查；通过后直接形成待核对输出，减少独立收尾请求。初始上下文完整时复用同一快照，移除无必要的查询入口；格式错误仅在现有总预算内有限反馈，网络和权限错误不自动重试。

新任务的负责人、工时和日期必须有讨论来源或明确继承依据。缺少支持时保留现有任务并转为具体中文追问。规则只检查可验证的来源线索，不能证明任意自然语言的全部语义；否定、条件和无法解释的日期应保守追问。已有任务的合法延期推导继续由规则和人工核对约束。

数组明确表示变更集，每个变更任务含完整字段。只去除与可信初始快照完全一致的既有任务；非法标识、重复标识、跨项目引用及真正修改的已完成任务不能被规范化隐藏。组长发布、来源校验、修订号和历史快照保持原约束。

## 评价与复现

旧结果、旧评分与 10 月 15 日 ZIP 保留。旧 provider 与 6 份依赖源码已从该 ZIP 提取到 `experiments/reliability_v3/baseline/` 并核对 SHA-256。新轮使用独立样例、明确的阶段语义和相同的等价变更规范化，再比较 v2 与 v3；调用前冻结，不根据输出修改标签。结果无改善时仍保留全部记录。
