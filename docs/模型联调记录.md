本机 `.env` 已配置 `https://openrouter.ai/api/v1` 和 `nvidia/nemotron-3-super-120b-a12b:free`，密钥只由服务端进程读取。配置状态为 `ai_ready=true`、`ai_status=ready`，接口不返回密钥。

正式网页入口为 `http://127.0.0.1:8000`。本轮后台以 `Start-Backend.ps1 -DirectModelConnection` 启动，模型主机名追加当前进程 `NO_PROXY`；没有修改系统代理或关闭 TLS 验证。普通代理路径曾出现 `APIConnectionError/ConnectError`，直连路径完成了以下全部场景。该结果不能单独证明所有网络异常都来自代理。

闭环测试使用独立演示库 `work/model-integration/20261013T113802621655Z/`。正式 `data/` 未重新初始化，原任务和计划未被测试改写。正式服务启用后，按正常恢复机制处理原有待分析消息，生成了真实 Agent 运行记录。

## 3. 兼容问题与修复

最小无参数工具预检遇到多余参数；真实计划生成在工具请求同时设置 `response_format=json_object` 时返回空对象。移除该组合后，项目查询与计划检查的原生工具调用正常。最终输出仍须通过 JSON 解析、Pydantic、消息来源、项目引用及规划约束校验，未放宽工具权限，也未增加模型直接发布路径。

原四轮预算不足以容纳两次查询、一次失败检查、一次修正检查和最终输出。现最多六轮模型请求，每轮最多五个工具调用，模型调用循环仍受默认 60 秒异步总超时控制，SDK 不自动重试。当前上下文已由绑定工具预查询，模型可复用，避免重复查询。

新增任务明确使用 `new_` 前缀，任何 `task_` 前缀仍保留给现有任务；约束错误文字与实际规则一致。追问使用成员姓名、工时、日期和验收标准，结构化任务字段仍按原协议返回。

新回归在修复前复现空对象校验失败，修复后用真实 `ProjectTools/check_plan` 验证错误标识反馈、有限修正、第五轮最终输出及累计用量。后端全量 **69 passed**；版本标签补充后，SDK/恢复定向回归 **3 passed**；本机 API **15/15 通过**。独立源码审查及启动参数复核 PASS。Starlette TestClient/httpx 的弃用提示仍存在，未为此修改用户 Python 环境。
