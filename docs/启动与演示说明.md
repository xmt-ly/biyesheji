# 启动与演示说明

## 1. 本机环境

项目目录为 `D:\DevelopTools\biyesheji`，指定 Python 为 `D:\Anaconda3\envs\face_env\python.exe`（3.12.12），本机 Node.js 为 24.11.1。后端依赖固定在 `backend/requirements.txt`，前端版本与依赖锁定在 `frontend/package.json` 和 `frontend/package-lock.json`。

从项目根目录安装后端依赖：

```powershell
Set-Location D:\DevelopTools\biyesheji
& D:\Anaconda3\envs\face_env\python.exe -m pip install -r .\backend\requirements.txt
```

`Build-Frontend.ps1` 和 `Start-Frontend.ps1` 在缺少 `node_modules` 时执行 `npm ci`，缓存保存在 `work/.npm-cache`。它们优先使用 PATH 中的 `npm.cmd`，否则使用 `D:\nodejs\npm.cmd`。下载依赖需要网络连接。

## 2. 启动方式

### 2.1 首次演示

```powershell
& .\scripts\Run-Demo.ps1 -DisableAI
```

脚本依次构建、初始化、启动，完成后访问 `http://127.0.0.1:8000`。演示账号见 README。演示初始化是显式操作，普通启动不会自动导入演示数据。已有演示记录不会因重复初始化而被清空。

### 2.2 日常运行

```powershell
& .\scripts\Start-Backend.ps1
```

后端从已有 `frontend/dist` 提供页面；改动前端后先运行 `Build-Frontend.ps1`，再刷新浏览器。若在后端启动时尚无构建目录，先构建后重启后端。

### 2.3 开发

```powershell
# 窗口一
& .\scripts\Start-Backend.ps1 -Reload
# 窗口二
& .\scripts\Start-Frontend.ps1
```

前端开发服务默认 5173 端口，代理 `/api` 与 WebSocket 到 8000 端口。后端通过 `-Port 8001` 可改端口；开发代理随之调整 `frontend/vite.config.js`。每个后端实例只允许一个 worker；内存中的实时广播和项目 worker 不支持跨进程协调。

## 3. 模型与数据配置

```powershell
if (-not (Test-Path -LiteralPath .\.env)) {
    Copy-Item -LiteralPath .\.env.example -Destination .\.env
}
```

仅在 `.env` 尚不存在时复制，避免覆盖已有配置。用编辑器填写：

```dotenv
LLM_BASE_URL=https://你的服务地址/v1
LLM_API_KEY=你的密钥
LLM_MODEL=供应商提供的模型名称
```

启动脚本只加载允许的配置键，支持单引号或双引号包裹值，不执行配置内容。用 Python/uvicorn 直接启动时应自行设置进程环境变量；程序不会自动读取 `.env` 或全局 `OPENAI_API_KEY`。不要把密钥填进前端、代码、论文或聊天记录。

`JWT_SECRET` 可选，需至少 32 字符；省略时使用持久化的 `data/jwt.key`。`DATA_DIR` 可选，默认 `data/`，数据库文件名为 `collaboration.db`，附件保存在 `files/`。备份脚本只支持项目目录内的数据目录。

模型配置后重启服务。登录后可看到 AI 配置状态；在聊天室发送讨论后，Agent 聚合连续消息，再进行分析和追问。主动按钮用于明确请求规划或在异常后重试。分析来源、待澄清问题和调用状态可在项目中查看；未配置时不会生成冒充模型的结果。

模型工具只读取当前项目上下文。建议先生成草案，成员反馈后由组长确认发布；发布前重新校验当前数据与规划约束。未满足的条件会明确展示，不能绕过校验发布。

### 3.1 本次验证过的 OpenRouter 配置

```dotenv
LLM_BASE_URL=https://openrouter.ai/api/v1
LLM_API_KEY=在本机填写
LLM_MODEL=nvidia/nemotron-3-super-120b-a12b:free
```

2026-10-13 的真实联调使用此模型，完成追问、任务草案、组长发布和延期调整。在本机代理路径出现连接异常、模型域名直连可用时，可运行：


该选项只把模型地址的主机名追加到当前进程 `NO_PROXY`，保留已有条目，不修改系统代理，也不关闭 TLS 验证。默认启动仍沿用进程代理配置。修改模型配置后须重启后端并刷新浏览器页面。

独立数据的真实模型闭环验证可重放如下（会调用供应商 API，程序单轮最多 12 次模型请求；输出不保存密钥或登录令牌）：

```powershell

Import-TaskEnv

```

数据与原始结果保存于 `work/model-integration/<时间>/`，不重置正式 `data/`。完整联调记录及本机连接条件见 `docs/模型联调记录.md`。

## 4. 建议的答辩演示路线

1. 教师登录，展示课程必做功能、验收条件和三个阶段；展示两个团队进度。
2. 组长登录一组，展示成员技能、每周可投入工时、需求和任务关系。
3. 在第二个标签页用 `member1` 登录；双方在聊天室发消息，观察实时同步与历史恢复。
4. 成员打开本人任务，查看任务说明、需求与验收条件，填写进度、剩余工时及阻碍。成员无法修改别人的任务或发布计划。
5. 已接入模型时展示 Agent 来源、追问及草案更新；未接入时使用明确标注的手工草案，演示依赖/工时校验和发布。
6. 组长查看草案与成员反馈、确认发布；展示计划版本及变更。延期时保留完成任务记录，通过调整草案修改未完成任务。
7. 团队提交阶段说明和交付物；教师审核为“需要修改”，团队重新提交，再审核通过。展示各次提交及教师意见。
8. 教师页面只有公开进度、计划和阶段成果，不显示聊天室和内部分析。切换到二组账号，确认不能访问一组数据。

公开演示账号只用于开发和展示。生产使用前应替换演示密码并补充账号管理。任务完成比例按完成任务数计算，不能当作成绩或成员贡献评分。

## 5. 备份与恢复

### 5.1 备份

为保持数据库与附件一致，先停止服务或停止所有写入操作，再执行：

```powershell
& D:\Anaconda3\envs\face_env\python.exe .\scripts\backup.py
# 自定义数据目录示例
& D:\Anaconda3\envs\face_env\python.exe .\scripts\backup.py --data-dir .\work\test-data
```

备份保存到 `work/backups/<时间>-<随机标识>/`，包含数据库快照、附件、存在时的 `jwt.key` 及 `manifest.json`。数据库使用 SQLite 备份接口；清单记录 SHA-256、附件数量和签名文件是否存在。备份包含项目资料和登录签名文件，应保存在可信位置。

### 5.2 保留现有数据的恢复

停止后端，选择一份完整备份；将它恢复到项目内一个**全新目录**，不覆盖原数据目录。例如：

```powershell
$taskBackup = 'D:\DevelopTools\biyesheji\work\backups\替换为实际备份目录名'
$taskRestore = 'D:\DevelopTools\biyesheji\work\recovered-data'
if (Test-Path -LiteralPath $taskRestore) { throw '恢复目录已存在，请另选新目录' }
$taskManifest = Get-Content -LiteralPath (Join-Path $taskBackup 'manifest.json') -Raw -Encoding UTF8 | ConvertFrom-Json
$taskHash = (Get-FileHash -LiteralPath (Join-Path $taskBackup 'collaboration.db') -Algorithm SHA256).Hash.ToLowerInvariant()
if ($taskHash -ne $taskManifest.database_sha256) { throw '数据库校验失败，停止恢复' }
New-Item -ItemType Directory -Path $taskRestore | Out-Null
Copy-Item -LiteralPath (Join-Path $taskBackup 'collaboration.db') -Destination $taskRestore
Copy-Item -LiteralPath (Join-Path $taskBackup 'files') -Destination $taskRestore -Recurse
if (Test-Path -LiteralPath (Join-Path $taskBackup 'jwt.key')) {
    Copy-Item -LiteralPath (Join-Path $taskBackup 'jwt.key') -Destination $taskRestore
}
```

在 `.env` 中将 `DATA_DIR` 改为恢复目录，然后启动后端。登录检查需求、任务、历史计划、聊天和阶段附件，确认无误后保留原目录作为回退。若使用外部 `JWT_SECRET`，恢复时保持相同配置；若变更签名密钥，需要重新登录。此版本没有数据库版本迁移工具，恢复应配套使用产生备份时的代码和 schema。

## 6. 验证与问题排查

```powershell
& .\scripts\Test.ps1
```

测试使用独立临时数据库，模型流程使用可控替身，不调用真实供应商。它们不能替代真实 API 联调和论文实验。

| 现象 | 处理 |
| --- | --- |
| 8000 端口被占用 | 停止自己先前启动的实例，或使用 `-Port` 指定空闲端口 |
| 登录失败 | 确认演示已初始化，密码为 `Demo2026!`，且服务读取正确的 `DATA_DIR` |
| AI 未配置 | 核对 `.env` 中三个 LLM 字段，重启后端，不使用 `-DisableAI` |
| AI 超时/输出异常 | 查看界面的运行状态，补充信息后重试；人工业务继续使用 |
| WebSocket 断线 | 页面自动重连并补取历史；检查后端是否运行、令牌是否过期 |
| 草案已过期或不能发布 | 打开校验结果，根据最新成员、需求、任务、课程信息修订后再确认 |
| 前端更新未显示 | 重新构建后刷新浏览器，必要时重启后端 |
| 脚本执行被禁止 | 只为当前 PowerShell 进程设置执行策略，按 README 操作 |

不通过日志输出模型密钥，不将 `data/` 和 `.env` 发布为静态文件。暂存联调材料位于 `work/`；这些材料与正式 `data/` 分开保存。
