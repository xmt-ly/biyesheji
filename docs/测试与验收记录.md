## 2. 重点回归范围

- 权限：跨项目消息、任务、文件和模型上下文隔离；教师禁止读取聊天室、内部卡片、运行记录和内部附件目录。
- 规划：需求与课程必做功能覆盖、依赖循环与时间冲突、周容量和阶段截止日期、完成任务保护、不可行计划。
- 发布：当前项目修订校验、成员不能发布、组长明确确认、重复发布不重复创建、事务与历史快照。
- Agent：消息聚合、工具边界、输出合法性、纠正关系、旧运行不能覆盖新卡片、失败不自动循环重试。
- 持久化：无聊天的 plan/adjust 意图、分析中断与新增输入、业务提交后广播中断、成功结果广播中断后的检查点。
- 边界输入：超过 SQLite int64 的 ID、无效 JWT subject、date.max、草案 PATCH 大小和 1200 项依赖链。
- 前端协作：迟到的登录/创建/分析响应不改写新会话或项目；断线期间新消息不跳过历史；持久确认后 HTTP 失败不显示重复待发项；未保存的成员资料不被队友刷新覆盖。

主要后端测试文件：`test_contract.py`、`test_agent_and_consistency.py`、`test_security_and_provider.py`、`test_review_regressions.py`、`test_quality_boundaries.py`。前端测试位于 `frontend/tests/`，备份测试位于 `scripts/tests/`。

## 3. 实际界面验收

使用本地演示账号，在互相独立的标签页进行以下操作：

1. 组长与 `member1` 登录一组，两条讨论消息实时出现在双方页面，作者和时间正确，未重复；刷新和重启后历史仍存在。
2. 成员打开本人任务，可以读取关联需求、负责人、日期、阶段、验收条件和依赖；保存进度 40%、剩余 4 小时及阻碍后，看板更新为“进行中/有阻碍”。
3. 组长创建明确标注人工来源的调整草案，关联成员讨论，将账号权限任务截止日期从 10 月 16 日改为 17 日。约束校验通过。
4. 成员提交核对意见并确认本人安排，页面没有发布入口；组长勾选最终确认后发布，生成计划 v2。版本页展示实际日期、剩余工时和进度变化，v1 保留原快照。
5. 上传演示 Markdown 材料，组长提交第一阶段 v1。教师给出“需要修改”，团队重新提交 v2，教师通过；旧材料、旧意见及关联计划 v2 均保留。
6. 教师页面没有团队协作入口或内部卡片；API 验证其消息、卡片、运行记录和内部文件列表均返回 403。已关联阶段的文件可下载，下载字节与原文件一致。
7. 二组访问一组消息/附件返回 403；普通成员修改他人任务或发布计划返回 403。再次发布已发布草案后仍为两项任务、两个一组计划版本。
8. 停止服务后备份，复制到新恢复目录并验证数据库、记录数量、附件与签名文件；正式源数据保留。重启正常恢复工作区和实时连接。

本机演示记录：6 个账号、2 个项目、4 项任务、2 条消息、3 份计划（两组合计）、2 次阶段提交。第一阶段通过只是演示审核结果，不代表正式项目已经完成课程验收。
