# 课程项目智能协作系统设计

版本：V1.0；日期：2026-10-11。本文记录初版架构与实现边界，接口字段以 API.md 和后端实际 OpenAPI 文档为准。验收结果在完成实际测试后单独记录。

## 1. 技术与部署

| 部分 | 方案 | 用途 |
| --- | --- | --- |
| 后端 | Python 3.12、FastAPI | 身份校验、业务接口、实时连接、Agent 调度 |
| 数据访问 | SQLAlchemy 2、SQLite | 用户、项目、消息、卡片、版本和阶段材料持久化 |
| 模型接入 | AsyncOpenAI、Chat Completions | 调用用户确认兼容的云端模型接口和函数工具 |
| 前端 | Vue 3、JavaScript、Vite | 学生工作区、教师管理、实时数据与卡片交互 |
| 测试 | pytest、FastAPI TestClient、前端行为测试 | 权限、数据一致性、规划、异常及界面行为 |
| 文件 | 项目数据目录、随机存储名 | 保存附件与元数据，通过鉴权接口下载 |

使用用户指定的 D:\Anaconda3\envs\face_env\python.exe。初版后端以一个进程运行；WebSocket 连接与调度属于该进程，持久化数据放在项目 data 目录。前端开发服务器将 /api 的 HTTP 与 WebSocket 请求代理到后端；生产演示使用构建后的前端资源。

SQLite 选型用于初版本机开发与多账号演示，提供显式初始化和备份恢复。课程、团队、聊天和阶段材料共用关系数据库，发布计划以一个事务写入。后续若采用多进程服务，实时广播和调度状态需要外部协调，不能直接依赖当前进程的连接表。

## 2. 总体结构

~~~mermaid
flowchart LR
    U[学生与教师浏览器] --> V[Vue 工作区]
    V -->|HTTP 业务请求| A[FastAPI 业务与权限]
    V <-->|WebSocket 学生消息| H[项目实时连接]
    A --> D[(SQLite 持久化数据)]
    H --> D
    H --> Q[项目级分析调度]
    Q --> C[项目上下文与工具]
    C --> D
    Q <-->|有限轮工具调用| L[云端模型]
    Q --> K[来源验证与约束检查]
    K --> D
    K --> H
    V -->|组长确认草案| P[发布与版本检查]
    P --> D
~~~

业务、广播、规划检查与模型接入分别组织。数据库会话按请求或后台工作单元创建；长时间等待模型不持有事务。模型返回后重新检查项目状态，持久化分析或发布业务变更。

## 3. 身份与数据范围

- 用户身份区分教师和学生。组长属于项目成员关系，而不是全局用户身份。
- 教师管理本人课程，读取关联团队的结构化进度、已发布任务计划和阶段成果。
- 学生访问本人加入的项目；普通成员可推进本人任务，组长协调和发布整体计划。
- 教师不能读取聊天室、原始消息、内部 Agent 卡片或含有私有讨论的运行记录。
- 所有业务对象、关联对象和模型工具的查询都校验项目范围。
- 附件通过后端鉴权下载。教师只获得已经进入允许查看的成果或阶段交付流程的文件。
- 前端的角色显示与按钮控制用于引导操作，服务端独立验证权限。

模型从服务端配置获取 LLM_BASE_URL、LLM_API_KEY 和 LLM_MODEL。配置状态接口只报告是否就绪和非敏感状态，不返回密钥。用户登录 token 与模型 API 密钥是两个不同的凭据。

## 4. 聊天与实时分析

### 4.1 消息流程

1. 校验用户身份和项目成员权限。
2. 用客户端消息标识检查重复发送，保存消息与发送者。
3. 广播已保存的消息，返回确认结果。
4. 将尚未分析的消息交给项目级调度器。
5. 重连客户端先补取遗漏的历史消息，再继续接收实时事件。

界面按消息 id 或客户端标识去重。切换项目或退出登录时关闭旧连接，防止旧项目消息进入新工作区。

### 4.2 调度边界

每个项目最多同时执行一个分析任务。连续消息聚合后分析，静默窗口与最大等待窗口共同限制启动时间。分析过程中到达的新消息保留为下一轮输入，持续讨论也能得到周期性处理。

调度器在去抖等待前持久化 AgentIntent，记录项目、分析模式和状态；AgentRun 关联实际消费的意图及消息范围。因此，没有聊天消息的手工规划请求、进度更新触发的调整也能在重启后恢复。运行中到达的新意图独立保留，停机中断的意图重新排队，恢复时读取最新项目数据。

完成检查点与结果在广播前提交；广播中断不能使已完成运行重新排队。同一批输入不重复生成业务建议。模型失败的意图标记失败，重启不会自动无限重试；由新输入或明确重试再发起分析。模型未配置或失败时显示明确状态，人工消息和其他业务继续工作。

### 4.3 输出与修正

输出包括摘要、问题、任务草案、来源消息和约束检查结果。Agent 可以针对负责人、工时、日期或依赖主动追问，下一轮分析读取关联回复及已有待处理卡片。

来源消息只能属于当前项目。模型引用不存在的消息、其他项目对象或非法任务时，后端拒绝该结果。后续讨论纠正事实时，旧卡片更新或标记失效，保留修正来源。

## 5. Agent 与工具

### 5.1 上下文

分析上下文包含当前课程要求及阶段日期、团队确认需求、成员技能与容量、任务状态、当前计划、有关讨论和待处理卡片。模型提示区分讨论内容与系统操作规则，聊天中的要求不改变工具权限。

消息的发送时间与项目时区参与相对日期解释。缺少必要信息时形成待澄清事项，不把猜测的负责人或工时作为已确认业务数据。

### 5.2 工具边界

| 工具能力 | 输入与输出边界 |
| --- | --- |
| 项目上下文查询 | 服务端绑定当前项目，输出其公开业务要求和成员、任务信息 |
| 任务查询 | 按当前项目检索，不接受切换到任意项目的指令 |
| 计划检查 | 接收草案，与现有任务合并后返回冲突、有效性及关联对象 |

模型可以决定是否及如何调用这些工具，但工具不会发布任务或直接修改教师日期。工具结果反馈到模型，修正过程受轮数和调用超时限制。

项目上下文先由服务端绑定工具查询并传入，模型可复用或按需重新查询。工具调用阶段不叠加 JSON 输出模式，兼容供应商原生工具协议；最终文本必须解析为 JSON 并通过结构与来源检查。最多六轮模型请求，每轮最多五个工具调用，模型分析总超时默认 60 秒，SDK 不自动重试。新任务使用 `new_` 前缀，现有任务使用与记录匹配的 `task_<id>`；约束失败允许有限修正，无法满足时留给团队协调。

最终结构化输出经过字段、来源与关系检查后成为分析卡片。模型的调用失败与格式错误保留可诊断、已脱敏的记录。

运行记录保存模型名称、提示协议版本、来源消息、工具结果、耗时及用量。当前协议版本为 `v2-tools`；更新协议不修改既有运行或计划快照。2026-10-13 已完成 OpenRouter 真实接口闭环联调，记录见 `docs/模型联调记录.md`，不替代后续固定样例对比实验。

## 6. 规划、约束与发布

### 6.1 规划结果

新任务具有稳定的草案 key；调整任务同时关联原任务 id。任务关联需求、负责人、验收条件、预计和剩余工时、依赖、开始及截止日期。

检查时把草案叠加到已有完整任务集合中，不能因为模型只列出部分任务而忽略原计划的容量或依赖。已完成任务保留原记录。

### 6.2 约束

- 引用的需求、成员、任务必须属于当前项目。
- 工时为有限且合法的数值，日期范围有效。
- 前置任务关系不能自依赖或形成循环。
- 时间安排满足前置任务和阶段截止约束。
- 成员剩余工作量不能超过其明确提供的当前项目容量。
- 确认需求通过任务关联检查结构覆盖；真实功能验收依赖测试和教师检查。

周容量的分配口径应在实际规划检查说明中明确，并与测试样例使用同一口径。系统不把技能标签或工时记录直接转为自动贡献评分。

### 6.3 发布事务

组长确认发布前，后端重新检查身份、草案状态、项目基础版本和约束。成员反馈属于草案核对记录。

第一版由组长查看团队反馈后进行最终人工确认，不强制每位成员分别投确认票。编辑草案后撤销旧反馈的确认标记，保留原反馈与失效记录；前端在发布前展示明确确认操作。

同一草案只发布一次。发布在一个事务中更新任务、生成计划快照、记录确认人并推进版本。相关项目状态已变化时，草案重新分析或核对；事务失败不能留下部分生效的数据。

任务、需求或成员容量变化推进项目业务版本。聊天室的新消息作为讨论输入记录，不能直接改变已发布计划；事实纠正通过卡片修正与明确发布流程反映。

进度、剩余工时和阻碍是执行中的实际反馈。合法的本人进度更新应保存，已有容量或排期风险作为检查结果展示并触发调整；新建或修改规划字段则执行发布前的硬约束检查。

模型结果同时校验项目业务版本与所引用卡片的状态、内容和反馈快照。旧结果不能使已经编辑、复核或发布的卡片失效。人工消息与模型卡片的更正关系需持久化，能够定位更正消息或新卡片。

### 6.4 延期调整

依据剩余工时及依赖图列出受影响的未完成任务。调整草案可以修改时间、建议分工和依赖，但保留教师截止日期与已完成记录。不可行安排输出冲突和协调事项。

计划页面以历史快照比较负责人、工时、依赖、任务和时间变化，不用当前任务数据重写历史版本。

## 7. 阶段交付与文件

课程可从草稿发布或归档；一旦发布或归档，不能退回私有草稿。已公开课程可以更新公开要求或归档，更新保存版本并使相关未发布草案重新核对。查询与模型上下文也检查课程可见性，防止历史异常关联暴露教师草稿。

三个检查阶段分别为需求与计划、开发中期和最终验收。提交包含说明、交付物、计划版本及当时进度快照。

每次重新提交形成新版本，教师审核保留操作者、时间、结果和意见。“需要修改”对应整改记录，不自动暂停学生日常协作。

文件元数据包含项目、上传者、原始文件名和内部存储标识。存储路径由服务端生成，客户端无法指定任意磁盘路径。下载校验身份和文件进入的业务流程。

教师只能下载阶段提交中关联的附件，无法枚举学生内部文件列表。上传文件不直接公开为静态资源，下载通过带身份验证的接口完成。

## 8. 验证与交付

验证覆盖三层：

1. 规划检查的单元测试：引用、循环、日期、周容量、完成任务保护和不可行情况。
2. 后端行为测试：身份、跨项目隔离、教师聊天室限制、发布幂等与过期、消息持久化、阶段历史及模型异常。
3. 前端与实际演示：登录、成员操作、实时消息、卡片交互、计划对比、教师阶段审核和错误状态。

云端接口凭据由用户配置。配置前只展示实际未配置状态；模型协议和异常流程通过受控测试替身验证，正式模型效果及论文实验通过真实接口测量并保留原始数据。

运行说明提供显式演示初始化、开发启动、生产构建、备份恢复和配置方法。实际验证结果、限制和验收覆盖记录在后续测试报告中。
